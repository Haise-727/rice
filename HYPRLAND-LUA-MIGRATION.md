# Hyprland `.conf` → `hyprland.lua` migration

**Done 2026-08-31.** Hyprland 0.56.2 warns that `.conf` support is removed in 0.57.
Written and verified, but **not yet active** - Hyprland only reads its config at
startup, so this takes effect at the next login.

## Layout

```
~/.config/hypr/
  hyprland.lua          entry: monitor, env vars, requires the rest
  lua/vars.lua          tunables (apps, gaps, sizes)      <- variables.conf
  lua/looks.lua         general/decoration/group/misc/animations
  lua/input.lua         input, cursor, gestures
  lua/rules.lua         window, workspace and layer rules <- rules.conf
  lua/execs.lua         autostart                         <- execs.conf
  lua/keybinds.lua      every keybind                     <- keybinds.conf
  scheme/current.lua    colours, generated by matugen
```

The `.conf` files are still there and are the rollback. They are now **stale** -
edits go to the `.lua` set.

## How it was verified

1. `Hyprland --verify-config -c ...` - parses without running. Used throughout.
2. The Lua API was read from `/usr/share/hypr/stubs/hl.meta.lua` rather than
   guessed, and uncertain dispatcher signatures were probed one at a time.
3. A **nested Hyprland** was launched on the live session with `lua/execs.lua`
   omitted (so it could not spawn duplicate daemons), and its resulting state was
   compared against the running `.conf` session.

Result: **118 distinct key combinations on both sides, none missing, none extra.**
Entry counts 121 (.conf) vs 119 (.lua), fully accounted for by the two deliberate
removals below.

## Deliberate changes

| Change | Why |
|---|---|
| dropped `Super+N -> makoctl dismiss --all` | mako is not the notification daemon any more; the bind was dead and shadowed Ashura's `Super+N` |
| merged the two `Ctrl+Super+Alt+Backslash` binds into one | `.conf` bound resize and center separately to the same key; one `hyprctl --batch` does both |
| 3-finger-down gesture repointed | ran `caelestia toggle specialws`, dead since caelestia was removed; now Ashura's dashboard zone |
| `wsaction.fish` replaced with native Lua | workspace-group switching spawned fish + jq + hyprctl on **every** keypress; `hl.get_active_workspace()` does it in-process |
| `submap = global` dropped | it was always active, so it behaved exactly like the default map |

## Gotchas worth remembering

- **`{ drag = true }` is a trap.** It registers a *release* bind (`bindr`), which
  breaks click-drag. Hyprland's own example config uses `{ mouse = true }`, which
  is correct. Caught by comparing bind kinds, not by `--verify-config`.
- The shipped `/usr/share/hypr/hyprland.lua` is **not** fully current - `mouse` is
  absent from `HL.BindOptions` in the stubs yet is the working key.
- Key strings use `+`, never commas: `"SUPER + SHIFT + 1"`.
- Lua rejects invalid escapes, so regexes need `[[long strings]]`: `[[org\.quickshell]]`.
- `hl.dsp.window.resize` takes pixels, not percentages. The one bind that wanted
  `exact 55% 70%` still goes through `hyprctl` to stay resolution-independent.
- `require` resolves relative to the config file's directory - no `package.path`
  needed for the real config.

## Still to check by hand

State comparison cannot prove runtime behaviour for these:

- **Super+LMB drag** to move a window, **Super+RMB** to resize (the `mouse = true` binds)
- `Super+U` (move out of group) and `Super+Shift+,` (lock group) - several Lua
  spellings all pass validation, so the semantically closest was chosen

## Rollback

Hyprland prefers `hyprland.lua` when it exists, so moving it aside is the entire
rollback:

```
~/.config/ashura/bin/hypr-config-rollback   # then log out and back in
```

If the Lua config errors badly, Hyprland enters **emergency mode** and binds
`SUPER + Q` / `SUPER + M` so a terminal is still reachable - confirmed during
testing when a broken harness copy failed to load. A TTY (`Ctrl+Alt+F2`) also works.

## What this unblocks

`hl.clear_crashed_lockscreen()` is present in the Lua API. That was the missing
piece that made qylock's `WlSessionLock` unsafe here - a crashed session lock is
now recoverable, so the animated lockscreen becomes viable. See COMPONENTS.md §26c.
