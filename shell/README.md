# rice-shell

A quickshell (QML) desktop shell. Own architecture; individual components adapted from
proven projects rather than hand-authored (see `../IMPLEMENTATION-PLAN.md`, UI sourcing rule).

## Layout
| Path | Role |
|---|---|
| `shell.qml` | root; loads zones via `ZoneLoader` |
| `config/Defaults.qml` | every tunable + its default. **This file is the config documentation.** |
| `config/Config.qml` | overlays `~/.config/rice/config.json` on the defaults; hot-reloads |
| `common/Colours.qml` | **generated by matugen** from the wallpaper — do not edit |
| `zones/ZoneManager.qml` | which screen-edge zones are open |
| `services/`, `modules/` | data sources and surfaces (to come) |

## Two things that bit us early
- **`Palette` is a built-in QtQuick type.** A singleton named `Palette` is silently shadowed and
  reads back `undefined`. Ours is `Colours`.
- **QML parses any property named `onFoo` as a signal handler**, so Material You's `on_primary`
  roles cannot be top-level properties. They are nested: `Colours.on.primary`.

## Zone rules
Zones on *different* screen edges may be open together (top + bottom). Zones sharing an edge are
mutually exclusive (top-left evicts top-right). Set `zones.perEdgeExclusive: false` to disable.
While the startup workspace is focused, `dashboardMode` hides every zone.

## Config
`~/.config/rice/config.json` overlays `Defaults.qml`. A missing key uses its default, so the file
stays small and cannot break the shell. Invalid JSON logs a warning and falls back to defaults.

## Running
    qs -p ~/rice/shell/shell.qml
